Runtime memory and diagnostics:
- Go writer batches flush at 64 MiB of reported source bytes or the configured
  record count. A single oversized record is preserved, not truncated; encoded
  and in-memory sizes can exceed source size. Copied producer slots release their
  references, and existing strings pass into protobuf fields without formatting.
- OLAKE_JAVA_HEAP_PERCENT is an optional per-child-JVM integer from 1 through 80.
  When set, the Go launcher appends -XX:MaxRAMPercentage to the child's
  _JAVA_OPTIONS after inherited options; other JVM options remain intact.
  An absent policy preserves the existing launch configuration. Explicit -Xmx
  still takes JVM precedence; startup logs report the actual max heap in bytes.
- Java metrics are disabled unless OTEL_EXPORTER_OTLP_ENDPOINT or
  OTEL_EXPORTER_OTLP_METRICS_ENDPOINT is configured. Standard OTLP headers,
  endpoint precedence, compression, TLS and resource attributes are supported.
  Metrics use HTTP/protobuf with default 15-second collection and 2-second
  export timeout, plus a 128-series per-instrument SDK cardinality cap. Traces and
  log export are disabled. Export failures do not fail ingestion; shutdown
  drains RPCs and performs a bounded final metric flush. Concurrent close callers
  wait for the in-progress flush before returning; collector/network failures
  remain bounded best-effort exports.
- Go and Java use their official OpenTelemetry SDKs and OTLP exporters. Resources
  follow the shared service.name/namespace/version/instance.id convention:
  SERVICE_NAMESPACE (or POD_NAMESPACE/localhost), GIT_HASH when available, and
  pod/host plus process identity. Standard OTEL_RESOURCE_ATTRIBUTES and
  OTEL_SERVICE_NAME override defaults. Pipeline-specific metrics remain bounded;
  they do not replace the SDK transport or imply automatic trace instrumentation.
- Runtime metrics cover CPU time, Linux RSS when available, heap used/committed/
  actual maximum, nonheap, direct/mapped buffer pools, GC count/time and threads.
  olake.stage.duration records seconds for conversion, parquet_write, flush,
  upload, commit and server-side rpc attempts, with bounded stage/outcome labels.
  Every datapoint explicitly includes job_id, component=iceberg-java and
  operation; table, file, row and request data are never metric dimensions.
  OLAKE_WORKFLOW_ID is resource context only, not a metric dimension.
- Index catch-up logs report from/to snapshots, per-snapshot operation and safe
  producer tags, selected files/records/bytes, and historical additions removed
  later in the traversed range. The removal count is not full target liveness.
  File byte counts describe whole data files, not projected or transferred bytes.
  Java file timings include downstream blocking; emitter summaries separately
  report monotonic readiness wait and send time. Go summaries separate receive,
  staging, intermediate durable flushes and final checkpoint; Pebble summaries
  separate row staging/Sync from new-file mapping Sync. Failures retain partial
  observations. New logs omit row identifiers, payloads and full file paths.
- Optional JFR requires both OLAKE_PROFILE_DIR and OLAKE_JFR_PROFILE_SECONDS
  (integer 1..300). A unique mode-0600 local file retains up to 64 MiB subject
  to JFR chunk granularity and the chosen duration. Only CPU samples/load and
  GC/heap-summary events are enabled, not JVM arguments, environment variables,
  system properties or file/socket I/O. No profiling listener is opened;
  recording failures are nonfatal. The existing opt-in debugger is loopback-only.
