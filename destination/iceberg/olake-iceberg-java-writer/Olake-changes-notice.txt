Runtime memory and diagnostics:
- Go writer batches flush at 64 MiB of reported source bytes or the configured
  record count. A single oversized record is preserved, not truncated; encoded
  and in-memory sizes can exceed source size. Copied producer slots release their
  references, and existing strings pass into protobuf fields without formatting.
- OLAKE_JAVA_HEAP_PERCENT is an optional per-child-JVM integer from 1 through 80.
  When set, the Go launcher appends -XX:MaxRAMPercentage to the child's
  _JAVA_OPTIONS after inherited options; other JVM options remain intact.
  An absent policy preserves the existing launch configuration. Explicit -Xmx
  still takes JVM precedence; startup logs report the actual max heap in bytes.
- Java metrics are disabled unless OTEL_EXPORTER_OTLP_ENDPOINT or
  OTEL_EXPORTER_OTLP_METRICS_ENDPOINT is configured. Standard OTLP headers,
  endpoint precedence, compression, TLS and resource attributes are supported.
  Metrics use HTTP/protobuf with default 15-second collection and 2-second
  export timeout, plus a 128-series per-instrument SDK cardinality cap. Traces and
  log export are disabled. Export failures do not fail ingestion; shutdown
  drains RPCs and performs a bounded final metric flush. Concurrent close callers
  wait for the in-progress flush before returning; collector/network failures
  remain bounded best-effort exports.
- Go and Java use their official OpenTelemetry SDKs and OTLP exporters. Resources
  follow the shared service.name/namespace/version/instance.id convention:
  SERVICE_NAMESPACE (or POD_NAMESPACE/localhost), GIT_HASH when available, and
  pod/host plus process identity. Standard OTEL_RESOURCE_ATTRIBUTES and
  OTEL_SERVICE_NAME override defaults. Pipeline-specific metrics remain bounded;
  they do not replace the SDK transport or imply automatic trace instrumentation.
- Runtime metrics cover CPU time, Linux RSS when available, heap used/committed/
  actual maximum, nonheap, direct/mapped buffer pools, GC count/time and threads.
  olake.stage.duration records seconds for conversion, parquet_write, flush,
  upload, commit and server-side rpc attempts, with bounded stage/outcome labels.
  Every datapoint explicitly includes job_id, component=iceberg-java and
  operation; table, file, row and request data are never metric dimensions.
  OLAKE_WORKFLOW_ID is resource context only, not a metric dimension.
- Index catch-up logs report from/to snapshots, per-snapshot operation and safe
  producer tags, selected files/records/bytes, and historical additions removed
  later in the traversed range. The removal count is not full target liveness.
  File byte counts describe whole data files, not projected or transferred bytes.
  Java file timings include downstream blocking; emitter summaries separately
  report monotonic readiness wait and send time. Go summaries separate receive,
  staging, intermediate durable flushes and final checkpoint; Pebble summaries
  separate row staging/Sync from new-file mapping Sync. Failures retain partial
  observations. New logs omit row identifiers, payloads and full file paths.
- Optional JFR requires both OLAKE_PROFILE_DIR and OLAKE_JFR_PROFILE_SECONDS
  (integer 1..300). A unique mode-0600 local file retains up to 64 MiB subject
  to JFR chunk granularity and the chosen duration. Only CPU samples/load and
  GC/heap-summary events are enabled, not JVM arguments, environment variables,
  system properties or file/socket I/O. No profiling listener is opened;
  recording failures are nonfatal. The existing opt-in debugger is loopback-only.

Atomic single-table resync:
- PREPARE_RESYNC creates a private same-identity metadata overlay before any
  format/schema mutation. Ordinary chunk transactions and CDC writers use it;
  old data and delete files leave only the staged current snapshot.
- PUBLISH_RESYNC requires every target writer closed successfully and commits
  once against the original base. UUID, main reference, schema, partition, sort
  and field identities are conflict-checked, including native REST assertions.
  REST applies the same original-to-final metadata delta as whole-metadata
  catalogs, preserving harmless concurrent properties. Publication keeps the
  original snapshot history, references and statistics and adds one complete
  overwrite snapshot parented to the original main snapshot. Fresh manifests
  describe all replaced files without rewriting Parquet; per-file data/delete
  sequences and V3 row IDs are retained. Private snapshots never enter history.
- The stable operation id, full saved-job checkpoint, original baseline SHA-256,
  generation and positive replacement snapshot id are committed together. The
  olake.resync.baseline-sha256 property hashes the raw UTF-8 canonical full-job
  checkpoint supplied by Go to PREPARE_RESYNC; active same-id prepares must match.
  Published PREPARE recovery accepts only that original full baseline or the
  exact published full checkpoint, never a newer target or unrelated-stream
  checkpoint. Legacy receipts without a baseline hash fail closed for recovery.
  Fresh staging clears previous receipt properties privately. Unknown publication
  outcomes retain staged files; ABORT_RESYNC is serialized with publication and
  leaves a terminal tombstone.
- Fresh attempts have a hard twelve-hour deadline before staging and publication,
  shorter than S3 Tables' minimum one-day unreferenced-file retention. Retries
  never reuse old attempt files. Custom storage cleanup must respect this bound.
  Resync REST clients cap connection timeout at 30 seconds and socket timeout
  at 60 seconds; execution-fenced REST catalogs inject SingleAttemptRESTClient
  through the public RESTCatalog client factory. Iceberg request/auth/mapper/
  parser APIs are retained; Apache automatic retries and redirects are disabled.
  Stock Iceberg 1.10.2 rejects max-retries=0, so no such setting is used.
  Catalog-side completion after a timed-out response remains an unknown outcome,
  not permission to delete files or advance the source checkpoint.
- Full index recovery applies equality, positional and deletion-vector deletes
  and explicitly projects metadata fields to preserve original file paths and
  physical positions. The durable replacement generation invalidates stale
  canonical index locations.
- Reserved olake_2pc and olake.resync.* properties are connector-owned. A table
  must have a single OLake job owner; direct external edits of reserved metadata
  are unsupported. Public resync never falls back to destructive table clearing.

- Runtime config execution-id/execution-fence requires fresh positive OPEN JSON
  reads before catalog startup, RPC work, destructive drops and catalog commits.
  Local paths and s3:// objects are supported. S3 reads use runtime default AWS
  credentials/region or OLAKE_S3_* files-storage environment overrides, never
  table FileIO or catalog-vended warehouse credentials. Missing, unreadable,
  malformed and wrong-runtime fences reject work. CLOSED rejects mutations but
  permits serialized ABORT_RESYNC/RESYNC_STATUS to retire/reconcile an attempt
  without erasing prior unknown publication. Unfenced standalone usage remains.
- EXECUTION_CAPABILITY is a read-only preflight RPC with no table/session setup.
  After a fresh fence read it reports protocol version 1, the actual configured
  execution_id, launch_id, recover_only and open fence_state. It never echoes
  request identity. Controlled callers must validate it before table operations;
  old/custom jars without the handshake fail closed rather than bypass fencing.
- resync-recover-only plus resync-launch-id permits only durable-marker recovery.
  Recovery PREPARE validates original launch and baseline/published checkpoint;
  missing publication is UNKNOWN with zero staging/index/schema/data/abort work.
  Publication atomically binds olake.resync.launch-id to the admitted launch.
  Every exception after publication dispatch, including a final HTTP 409 after
  an ambiguous earlier request, reconciles the durable marker or remains UNKNOWN.
  A local pre-dispatch metadata conflict is still definitive non-publication.

- EXECUTION_RETIRE (13) is a read-only ordinary-operation terminal RPC. A fresh
  matching OPEN or CLOSED fence is required. It seals JVM-wide catalog mutation
  admission and returns version=1, execution_id, launch_id, command and outcome
  from startup execution-id/execution-launch-id/execution-command and the actual
  dispatch tracker, never request metadata. Ordinary commands are sync and
  clear-destination. Startup EXECUTION_CAPABILITY still requires OPEN.
  Outcomes are not_started, settled or sticky unknown; settled means completed
  remote catalog calls, not overall command success. A local conversion failure
  does not itself make completed catalog work ambiguous. Go binds settled proof
  to the complete saved checkpoint; Java does not fabricate that state hash.
  All SingleAttemptRESTClient roots/auth clones share runtime dispatch tracking.
  Active dispatch at sealing, transport exceptions and mutating HTTP errors
  remain unknown; a single-attempt DELETE 404 is definitive only without prior
  ambiguity. OAuth form exchange and catalog reads are not table mutations.
  Non-REST create/namespace/drop/commit authority is conservatively unknown:
  its retry/completion behavior is not certified by this transport tracker.
